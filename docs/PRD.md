# Momo · 默默｜产品需求文档

> 项目：情绪日记与自我关怀 · 可交互静态原型  
> 版本：1.0 · 2026 年 10 月 7 日  
> 适用端：桌面网页展示页 + 手机网页交互原型  
> 定位：求职压力下的私人短记录与按需自助支持

## 01 产品目标

让正在求职的年轻人随手留下一句当下想法，回看情绪变化；当用户主动提出需要时，帮助拆分情绪触发因素，并提供可以选择执行的小行动。

本轮交付一套无需账号、可直接打开体验的 HTML 静态网页。中心是一台可操作的 iPhone 模拟器，外围说明用户需求、创作者的研究路径、关键设计取舍与使用的工具。手机访问时优先展示可操作的产品界面，研究信息依然可以继续阅读。

## 02 用户定位与使用场景

主要用户是处于投递、面试、等待结果或同龄比较情境的应届求职者，优先服务报告中需要私密表达、避免比较的用户状态。职场早期求职者是可迁移的次要场景。核心问题是缺少没有评价压力的表达空间，同时希望在需要时得到具体帮助，但不愿承担复杂记录、公开分享或坚持打卡的负担。

证据依据是[用户洞察报告](report.html)中整理的两份 Atypica 报告与研究过程；它们属于 AI 角色模拟与定性假设，不是已经完成的真人可用性测试。报告识别的外部不公 / 维权需求需要长事实记录与跨用户证据，本轮明确不宣称完整覆盖。

方法与风险编号的完整核对见[来源核验与设计证据](source-evidence.md)。

核心场景按优先级排序：

1. 刚结束一次不满意的面试，写一句原话，立即离开。
2. 晚些时候翻到那张卡片，主动问 AI，从事件中找到可控的下一步。
3. 等待消息、想起同伴比较时，暂不分析，先选一段呼吸、声音或走动。
4. 回看近期的情绪标记与记录，理解什么事件经常影响自己。

## 03 原型成功标准

本轮衡量可理解性、任务可完成性与能力边界，不承诺临床效果。

| 目标 | 交付验收标准 |
| --- | --- |
| 低负担记录 | 可以直接输入并保存 1–50 字的想法，无必填标题、分类或账号 |
| 私密、不被评价 | 不存在其他用户内容、点赞、排行或 AI 自动评价 |
| 情绪变化可见 | 示例与新记录能够通过时间、情绪标签或回看入口理解变化 |
| AI 按需出现 | 只有用户点击“问 AI”后才进入建议 / 对话 |
| 建议具体 | 示例包含触发因素分析，以及可选择的小行动 |
| 自助调节完整 | 至少覆盖呼吸 / 冥想、舒缓声音 / 音乐、轻量走动三类 |
| 静态边界透明 | 新建记录点击“问 AI”后说明未接入模型，并可查看示例 |
| 多端可用 | 桌面可点击操作；手机可触摸滑动；窄屏无横向溢出 |

## 04 核心设计原则

**记录先于解释。** 首访先给一张可直接输入的空白卡，将第一句话留给用户。保存的是用户的表达，不强制改写成积极话语，也不立即解释其意义。

**AI 由用户发起，也可以不被看见。** 主动问 AI 是对话起点；不通过自动弹窗、推送或评语制造求助需求。只记录状态允许隐藏求助入口，回应概念报告关于按钮本身也可能制造压力的风险。

**每次只给一点可做的事。** 示例建议优先给出一个可控的小行动，再允许继续追问；不倾倒长篇建议清单。

**可随时结束。** 不设置连续天数、目标完成率或“未处理情绪”。用户不完成练习也不受到提醒或评价。

**历史可取回，视觉不堆积。** 界面最多显示五张卡片；卡片总量与可见层数分离。

**演示边界明确。** AI 对话、触发分析与引用演示均不能暗示已经联网生成。示例内容应有示例标识。

## 06 功能需求

### F01 首次进入与操作提示 · P0

当前浏览器尚无个人记录时，首页默认是一张可直接书写的空白想法主卡，左下方露出两张重叠的卡片背面，保留卡片堆叠的视觉提示。卡背不展示预置日记、历史文字或情绪标签。先把表达空间交给用户，避免刚进入就被示例中的负面情境影响。示例仍可在主动向左翻阅或点击“更早的想法”后查看；保存后才出现对应记录的“问 AI”入口。

初次打开时给出简短且可关闭的操作说明：直接写想法；向左翻看历史；向右回到更新记录或在最新位置回到空白卡；保存后可按需点击“问 AI”。桌面同时提供可发现的按钮，避免只能依赖手势。操作提示不遮挡全部产品内容，不要求用户填写资料。已有个人记录时再次访问，优先显示自己的最新记录。

验收：无个人记录时首页显示一张空白输入主卡和左下方两张无内容卡背，不露出示例文字与情绪；用户可以关闭提示并直接输入；主动翻阅后仍能访问示例；主要动作有可读标签；不存在必须读完才能继续的长教程。

### F02 记录一条想法 · P0

用户在新建卡片中输入 1–50 字，情绪选择为可选项。以字符为限制，不把一个中文字符当作多个字节；使用表情符号时也应避免截断字符。空白内容不能保存，超过上限有清晰反馈。

保存后，新笔记进入卡片序列并成为当前卡片。无需填写标题，也不自动生成 AI 评价。若使用浏览器本地存储，应明确记录仅保存在当前浏览器，清除浏览器数据后可能丢失；不使用“永久私密”或“云端加密”等未实现承诺。

当前实现将笔记、尚未保存的草稿、可选情绪与只记录偏好保存到当前浏览器。字数按完整字形计数，支持组合表情；超限时保留输入并禁用保存，避免静默截断。记录日期按北京时间展示。

验收：中文、英文与表情输入不破坏布局；保存成功后立即可见；若承诺本地保存，刷新后应保留；非法输入不会生成空卡片。

### F03 翻看历史与新建 · P0

浏览已保存记录时，当前卡片之外最多显示左侧两张和右侧两张。可见层数始终不超过五张；更早的内容保留在数据中，只在持续翻阅时进入可见窗口。空白输入状态显示一张主卡与左下方两张无文字、无情绪标签的卡背，不渲染历史内容预览。

从空白卡向左滑进入最新的已保存记录，再向左进入更早的记录。向右滑回到更新记录；在最新记录处继续向右回到空白卡。往返翻阅时保留未保存草稿。同时提供前后翻页按钮或明确的新建入口，支持鼠标、键盘和不熟悉手势的用户。

验收：长历史不会生成无穷堆叠；首尾边界清楚；不会跳过或丢失记录；新建入口可重复到达。

### F04 预置卡片与 AI 对话 · P0

预置内容覆盖面试受挫、等待反馈、同伴比较、自我恢复等求职情境。每张示例卡片可包含日期、短文本、情绪、触发因素与对应示例对话。所有示例数据标识为演示内容，不冒充当前用户的历史。

“问 AI”打开与当前卡片一致的对话。首屏引用原始想法，说明对话与建议为预设示例。对话先描述已知事实和可能需要澄清的内容，再给可以选择的下一步。通过预设回复按钮继续演示时，应保持上下文连贯，并允许返回卡片。

提供“只记录 / 隐藏问 AI”的轻量入口与可恢复状态。隐藏后卡片不显示建议按钮，不出现待处理提示；该选择不影响保存、翻阅、回看或独立进入“照顾自己”。

验收：不会打开其他卡片的对话；AI 不在首页主动评价；只记录状态可进入与恢复；至少一个完整示例展示“澄清 → 触发因素 → 可控行动”的路径；不使用未经证实的引用或伪造联网来源。

### F05 新笔记的 AI 边界 · P0

用户新写的记录可以保存与回看，但不接入真实模型。在新笔记中点击“问 AI”，显示简短解释，并给出“查看示例对话”和“回到我的记录”等动作。示例入口必须明确切换到了演示内容，不能让用户误以为是针对新笔记生成的分析。

推荐文案：“这版原型还没有接入 AI。你的想法已留在这里，可以先看看示例中，我们会怎样一起拆解问题。”

验收：不出现假生成进度；不对用户的新文本输出通用结论并伪装成分析；查看示例后仍能找到刚保存的笔记。

### F06 情绪变化与触发因素 · P0

用户可以从近期记录中了解情绪随时间的变化。情绪采用用户自选或预置示例标签，缺省值保留为未标记，不通过文字自动推断新记录的心情。触发因素来自预置对话的情境解释，并标为示例分析。

当前实现将“我的记录”与“示例记录”分为两个标签页。时间点展示最近最多七条记录，各点处于相同高度；下方可打开具体卡片。自己尚无记录时显示空状态，允许直接新建，不要求补写历史。

回看不设好坏评分、达标状态或“必须积极”的目标，不用连续下行折线强化负面累积。采用时间、事件与温和的自述情绪标签，并保持入口次级。样本不足时明确说明，避免把几条演示数据表达成真实统计规律。用户可以回到具体卡片，理解情绪标记所对应的事件。触发分析优先描述事实场景，不擅自点破用户未表达的深层动机。

验收：情绪与记录日期对应；未标记记录不被补成某个情绪；示例趋势不与用户新记录混淆；触发因素能够追溯到日记情境。

### F07 自助调节 · P0

提供三类按需入口，每类都说明预计投入与可以随时停止：

| 类型 | 原型内容 | 交互要求 |
| --- | --- | --- |
| 呼吸 / 冥想 | 1 分钟呼吸节奏、文字阶段与呼吸圈 | 用户主动开始，可暂停、继续、提前结束 / 返回；不自动播放 |
| 声音 / 音乐 | 2 分钟本地合成风声与轻柔音调 | 实际音频播放，可暂停和调节音量；离开后停止；音频失败时明确提示 |
| 轻量走动 | 5 分钟轻活动引导，分为准备、慢走、结束三阶段 | 可查看阶段、开始、暂停或提前结束；不作治疗效果承诺 |

内容用于日常自我关怀，不替代专业支持。舒缓入口可以从首页直接进入，不强制先写日记或与 AI 对话。

练习结束后可以选择“松一点了 / 差不多 / 更紧绷了”或跳过。当前仅用于本次交互反馈，不生成日记，不写入长期情绪记录，不计入回看、导出、完成次数或连续天数。用户离开练习页面时，音频和计时器会停止。

### F08 桌面与手机响应式展示 · P0

桌面以中心 iPhone 为视觉锚点，两侧或下方呈现用户洞察、创作者思考与工具链。手机保留完整交互，并将外围内容顺序排在产品体验之后。iPhone 视觉包括合理的圆角、边框和屏幕安全区域；内部文字与按钮不被设备装饰遮挡。

验收：桌面常见宽度与手机窄屏均可阅读；操作目标适合触控；产品内部和外层页面滚动关系清晰；减弱动画偏好得到尊重。

### F09 设计过程与交付入口 · P0

展示页应解释“为什么这样设计”，而不只列功能。必须体现创作者的四点观察、卡片堆叠风险的处理、用户主动问 AI 的原因，以及原型阶段的取舍。工具说明准确区分：Atypica 用于前期 AI 研究与概念验证；创作者作出产品判断；Codex 用于文档、HTML / CSS / JavaScript 原型和验证。

提供用户洞察报告、PRD 和原型图入口。外部研究链接可以追溯原材料，但不把外部 AI 报告当作真人调研成果。

### F10 个人记录的导出与清除 · P0

“回看”底部提供“导出我的记录”和“清除我的记录”。导出生成 JSON 文件，包含用户自己保存的日记及日期、情绪，不包含预置案例。导出文件不包含未保存草稿、模式偏好或练习结束反馈；本轮不提供文件导入功能。

清除前显示影响范围与确认操作，也提供先导出的入口。确认后清除当前浏览器中个人日记与草稿，预置案例保留，操作无法在产品内撤销。仅清除日记与草稿，不重置只记录模式等偏好。

验收：有个人记录时可导出并读取文件；示例不混入导出；取消清除时数据仍在；确认清除后刷新也不再显示个人记录；返回示例仍可正常体验。

## 07 风险回应与范围取舍

账号与登录、跨设备同步、云数据库、公开社区、评论和点赞、打卡、排行榜、心理量表或诊断、真实大模型接入、真实第三方平台抓取、支付、推送、求职岗位匹配与咨询预约。概念报告提出的独立长事实补充通道、阶段归档在本轮延后；当前用五张可见窗口控制展示负担，此举不等于已经证明长期积压风险消失。

风险对应关系：报告风险一由五张窗口与次级回看回应；风险二由只记录 / 隐藏 AI 入口回应；风险三由缩小用户范围、透明说明与后续证据计划回应。创作者提到的联网经验参考属于第三项风险，不能替代第二项的交互处理。

后续可探索联网经验参考，但必须验证来源可用性、使用授权、时效、引文与观点偏差。尤其是维权场景，不能把社交帖子当作事实或法律结论。本轮不生成貌似真实的小红书、抖音出处。

## 08 关键用户流程

**流程 A · 留下想法：** 首次提示 → 首页空白卡 → 直接输入短句 → 可选情绪 → 保存 → 新卡片出现；已有个人记录时再次访问先显示自己的最新记录。

**流程 B · 回看与主动求助：** 左翻历史 → 选中示例卡片 → 问 AI → 阅读预设追问与建议 → 选择预设回应 → 返回卡片。

**流程 C · 新笔记求助边界：** 新建并保存 → 问 AI → 看到静态原型说明 → 查看示例或返回 → 自己的记录保留。

**流程 D · 不分析也可以：** 首页 → 舒缓空间 → 选择呼吸 / 声音 / 走动 → 主动开始 → 随时停止 → 返回。

**流程 E · 理解产品设计：** 桌面展示页 → 用户洞察与思考 → 研究原文 / 交付文档 → 回到中心手机体验。

## 09 数据与实现约束

| 数据对象 | 最小字段 | 约束 |
| --- | --- | --- |
| 日记 | id、text、createdAt、emotion、isDemo | emotion 可为空；text 为 1–50 字；示例与用户记录分开标识 |
| 示例对话 | noteId、messages、quickReplies、triggers、actions | 只能关联示例；对话内容本地预置 |
| 体验状态 | currentNote、currentView、onboardingSeen、aiVisible | 页面跳转不应导致已保存记录消失；只记录状态可恢复 |
| 舒缓状态 | activity、isRunning、elapsed / phase、feeling | 仅会话内状态；切换、停止与离开时清理计时器 / 音频，反馈不长期保存 |

实现使用静态 HTML、CSS 与 JavaScript，避免要求用户安装依赖才能体验。若需要开发服务器用于截图或检查，交付仍需说明最简单的打开方式。关键文案与示例数据应易于维护。

## 10 内容、隐私与支持边界

示例建议使用克制、具体、不评价人格的语言，例如“把最卡住的那一道题写下来，明天只练这一题”。不使用“你一定会成功”“你的情绪完全不合理”等安慰或评判。

原型不采集账号资料，不上传日记到模型。若使用本地保存，页面说明当前浏览器的存储边界。产品不声称提供治疗、诊断或危机响应能力。真实产品上线前，需要单独制定高风险表达处理和人工支持策略，并验证适用于目标地区的资源。

“私密”在本轮指没有公开发布、没有发送到服务器；不等同于设备加密或访问控制。共用设备、浏览器数据清除以及不同浏览器 / 不同访问地址之间的存储隔离，应在交付说明中明确。导出文件由用户自行保存。

## 11 可访问性与异常状态

| 状态 | 期望行为 |
| --- | --- |
| 首次打开 | 有简短提示与可关闭入口 |
| 空白输入 | 保存不可用或给出明确反馈 |
| 字数超限 | 保留用户输入意图，说明限制，不静默损坏字符 |
| 历史首尾 | 方向和新建行为明确，无空白死路 |
| 未选情绪 | 仍可保存，显示为未标记 |
| 新笔记问 AI | 说明静态边界并给出示例入口 |
| 浏览器存储不可用 | 页面可继续体验，提示本次内容可能无法保存 |
| 音频不可用 | 提供明确反馈，不持续展示播放成功状态 |
| 键盘操作 | 输入、保存、导航、关闭浮层与返回可以完成 |
| 减弱动画 | 关闭或简化大幅滑动与持续装饰动画 |

## 12 交付与验收清单

- 用户洞察报告：来源、证据限制、目标用户、痛点场景、设计推导与后续验证计划。
- PRD：功能优先级、用户流程、静态边界、多端要求和可执行验收项。
- 若干原型图：桌面整体、手机日记、新建想法、AI 对话、情绪回看、照顾自己、呼吸练习，共七张 JPEG，集中展示于原型图总览页。
- 可交互产品：可打开、可翻阅、可新增、可查看示例对话、可体验自助调节。
- 交付说明：启动方式、文件入口、测试范围和已知限制。

验收按真实动作完成：打开桌面页与手机视图；确认无个人记录时首页显示空白输入主卡及左下方两张无内容卡背，不露出示例内容；关闭引导；直接保存含中文和表情的新记录；刷新并核对自己的最新记录；连续翻阅历史并返回空白卡，确认草稿保留；确认可见卡片不超过五张；从示例卡片进入对应对话；隐藏并恢复 AI 入口；新笔记求助时看到边界说明；查看情绪与触发因素；逐一操作三类舒缓入口；检查文档与原型图链接。

文件对应关系：桌面总览 `prototypes/01-desktop.jpg`；手机首页 `02-mobile.jpg`；新建 `03-write.jpg`；AI 示例 `04-ai.jpg`；回看 `05-review.jpg`；照顾自己 `06-care.jpg`；呼吸练习 `07-breathing.jpg`。原型图由实际网页状态截图，不作为已经完成用户测试的证据。

## 13 后续验证与版本方向

先验证短记录、翻阅方向、主动求助与建议结构是否被理解，再决定是否接入真实模型。模型接入前还需要验证内容质量、引用真实性、隐私说明、数据留存、错误恢复与支持边界。功能扩展以减少用户负担为前提，不因为可实现而添加社交、排行或强制打卡。
